# 技术架构与数据接口（草案）

## 1. 系统分层

```text
┌──────────────────────────────────────────────┐
│ 训练/比赛应用                                 │
│ 事件记录、统计、提示、对接 smartpaddle/乒云    │
└──────────────────────┬───────────────────────┘
                       │ measurement event
┌──────────────────────▼───────────────────────┐
│ 识别与标定                                     │
│ 球检测、轨迹拟合、球网平面、参考线、置信度     │
└──────────────────────┬───────────────────────┘
                       │ frames / sensor samples
┌──────────────────────▼───────────────────────┐
│ 采集设备                                       │
│ 相机、补光、可选深度/ToF、主控与通信           │
└──────────────────────┬───────────────────────┘
                       │ calibration reference
┌──────────────────────▼───────────────────────┐
│ 机械基准                                       │
│ 左右夹具、延长杆、刻度、参考线、安装定位       │
└──────────────────────────────────────────────┘
```

机械基准应当可以独立使用；识别系统不应把“图像中的一条线”当作唯一的高度依据。

## 2. 首版识别流程

1. 检查左右夹具是否安装、延长杆是否锁定；
2. 识别球网平面和参考线/高度标记；
3. 用已知高度点完成像素坐标到实际高度的标定；
4. 检测乒乓球，建立短时轨迹；
5. 将轨迹外推或插值到球网平面 `x = 0`；
6. 计算 `h_cross`、`delta_h` 和结果分类；
7. 结合清晰度、轨迹长度、标定状态和遮挡情况生成置信度；
8. 保存原始事件和可复核的中间数据。

## 3. 设备状态

```text
idle → setup → calibrating → ready → capturing → result
                      │            │             │
                      └────────────┴────── fault ┘
```

- `idle`：设备未开始工作；
- `setup`：检查夹具、延长杆和相机视野；
- `calibrating`：建立球网平面与高度映射；
- `ready`：标定有效，可以采集；
- `capturing`：正在采集或跟踪球路；
- `result`：产生一条过网测量结果；
- `fault`：标定失效、设备断开或数据质量不足。

## 4. 测量事件格式（草案）

```json
{
  "schema_version": "0.1",
  "event_id": "2026-08-23T00:00:00.000Z-000001",
  "device_id": "smartgear-net-height-001",
  "timestamp_ms": 0,
  "net_plane": {
    "coordinate": "x=0",
    "calibration_id": "cal-0001"
  },
  "reference_height_mm": 185,
  "crossing_height_mm": 191.4,
  "height_delta_mm": 6.4,
  "classification": "above",
  "confidence": 0.92,
  "quality_flags": []
}
```

字段单位统一使用毫米；未知或无效结果必须通过 `classification: "unknown"` 和 `quality_flags` 表达，不能用 0 代替。

## 5. 首版实现边界

首版优先验证测量闭环，暂不包含：

- 正式比赛裁判判定；
- 多球、多台球桌的集中管理；
- 复杂三维弹道重建；
- 固定某一品牌或型号的相机；
- 将所有数据直接绑定到现有训练应用的内部实现。

## 6. 目录约定

- `hardware/`：机械结构、装配图、物料清单和尺寸记录；
- `firmware/`：主控和传感器设备代码；
- `vision/`：采集、标定、球检测和高度估计；
- `software/`：调试工具、数据查看和外部接口；
- `docs/`：决策、测试记录和协议版本。
